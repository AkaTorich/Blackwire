# Сеть охраны музея

Защищённый экспонат переместили, когда охранная смена была пуста.

## Начало

1. Положи эту папку рядом с другими плагинами и нажми «Перечитать».
2. Открой окно подсказки командой `museum_security_network_open` или нажми «Старт».
3. В терминале запусти `museum_security_network_start`.
4. Прочитай письмо «Сеть охраны музея: первая зацепка» в игровой почте.
5. Открой `http://198.22.29.1/` в игровом браузере и запусти `probe 198.22.29.1`.
6. Пройти через шлюз и забрать внутренний архив.

## Подсказки

Механика взлома: integer_overflow. Подсказки и параметры конкретного устройства даёт research.

- Если `probe` показывает активный файрвол, обойди его командой `firewall <адрес>`. При промахе попробуй ещё раз и следи за подозрением.
- На первом узле ищи собственную службу плагина — `exhibit_archive`.
- Для доступа нужно слабое место «entry», а не просто утечка данных.
- Внутри устройства посмотри `/etc/maintenance-note.txt` — там адрес записи.
- Команда `museum_security_network_status` показывает прогресс без сброса.
- Награда: 198 ₵, выплачивается один раз. Повторный запуск Start не дублирует содержимое и не сбрасывает прохождение.

## Если хочешь готовое решение

`research -h 3 198.22.29.1 museum_security_network:gateway_entry`

Свой исходник: `exploit new ~/scripts/my_exploit.adr 198.22.29.1 museum_security_network:gateway_entry`. Заполни payload по подсказкам в игре.

Готовый редактируемый инструмент: `market buy exp_integer_overflow`.

`exploit -f ~/scripts/exp_integer_overflow.adr -s museum_security_network:gateway_entry 198.22.29.1`

Прочитай `/srv/records/exhibit-moves.csv` на последнем узле — там сохранённая запись.

## Установка и память

Семейство: сети. Организация: центр безопасности. Папка плагина не трогает чужие сохранения; созданные устройства и задания сохраняются вместе с миром.
