# Инцидент с просроченным пропуском

Временный пропуск продолжает работать уже после окончания смены.

## Начало

1. Положи эту папку рядом с другими плагинами и нажми «Перечитать».
2. Открой окно подсказки командой `expired_badge_incident_open` или нажми «Старт».
3. В терминале запусти `expired_badge_incident_start`.
4. Прочитай письмо «Инцидент с просроченным пропуском: первая зацепка» в игровой почте.
5. Открой `http://198.22.93.1/` в игровом браузере и запусти `probe 198.22.93.1`.
6. Поймать запись инцидента и пройти по его таймлайну.

## Подсказки

- Если `probe` показывает активный файрвол, обойди его командой `firewall <адрес>`. При промахе попробуй ещё раз и следи за подозрением.
- На первом узле ищи собственную службу плагина — `badge_control`.
- Для доступа нужно слабое место «entry», а не просто утечка данных.
- Внутри устройства посмотри `/etc/maintenance-note.txt` — там адрес записи.
- Команда `expired_badge_incident_status` показывает прогресс без сброса.
- Награда: 116 ₵, выплачивается один раз. Повторный запуск Start не дублирует содержимое и не сбрасывает прохождение.

## Если хочешь готовое решение

`exploit -s expired_badge_incident:records_entry 198.22.93.1`

Прочитай `/srv/records/badge-status.csv` на последнем узле — там сохранённая запись.

## Установка и память

Семейство: события. Организация: корпорация. Папка плагина не трогает чужие сохранения; созданные устройства и задания сохраняются вместе с миром.
