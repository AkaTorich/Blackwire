# Утечка в ротации резервных копий

Ротационный резерв показывает устаревший манифест до того, как его перезапишут.

## Начало

1. Положи эту папку рядом с другими плагинами и нажми «Перечитать».
2. Открой окно подсказки командой `rolling_backup_leak_open` или нажми «Старт».
3. В терминале запусти `rolling_backup_leak_start`.
4. Прочитай письмо «Утечка в ротации резервных копий: первая зацепка» в игровой почте.
5. Открой `http://198.22.92.1/` в игровом браузере и запусти `probe 198.22.92.1`.
6. Поймать запись инцидента и пройти по его таймлайну.

## Подсказки

- Если `probe` показывает активный файрвол, обойди его командой `firewall <адрес>`. При промахе попробуй ещё раз и следи за подозрением.
- На первом узле ищи собственную службу плагина — `backup_sync`.
- Для доступа нужно слабое место «entry», а не просто утечка данных.
- Внутри устройства посмотри `/etc/maintenance-note.txt` — там адрес записи.
- Команда `rolling_backup_leak_status` показывает прогресс без сброса.
- Награда: 108 ₵, выплачивается один раз. Повторный запуск Start не дублирует содержимое и не сбрасывает прохождение.

## Если хочешь готовое решение

`exploit -s rolling_backup_leak:records_entry 198.22.92.1`

Прочитай `/srv/records/backup-rotation.csv` на последнем узле — там сохранённая запись.

## Установка и память

Семейство: события. Организация: корпорация. Папка плагина не трогает чужие сохранения; созданные устройства и задания сохраняются вместе с миром.
