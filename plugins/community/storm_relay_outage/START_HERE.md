# Шторм на прибрежном реле

Прибрежный ретранслятор теряет связь с базой на фоне учебной шторма.

## Начало

1. Положи эту папку рядом с другими плагинами и нажми «Перечитать».
2. Открой окно подсказки командой `storm_relay_outage_open` или нажми «Старт».
3. В терминале запусти `storm_relay_outage_start`.
4. Прочитай письмо «Шторм на прибрежном реле: первая зацепка» в игровой почте.
5. Открой `http://198.22.91.1/` в игровом браузере и запусти `probe 198.22.91.1`.
6. Поймать запись инцидента и пройти по его таймлайну.

## Подсказки

Механика взлома: double_free. Подсказки и параметры конкретного устройства даёт research.

- Если `probe` показывает активный файрвол, обойди его командой `firewall <адрес>`. При промахе попробуй ещё раз и следи за подозрением.
- На первом узле ищи собственную службу плагина — `storm_relay`.
- Для доступа нужно слабое место «entry», а не просто утечка данных.
- Внутри устройства посмотри `/etc/maintenance-note.txt` — там адрес записи.
- Команда `storm_relay_outage_status` показывает прогресс без сброса.
- Награда: 100 ₵, выплачивается один раз. Повторный запуск Start не дублирует содержимое и не сбрасывает прохождение.

## Если хочешь готовое решение

`research -h 3 198.22.91.1 storm_relay_outage:records_entry`

Свой исходник: `exploit new ~/scripts/my_exploit.adr 198.22.91.1 storm_relay_outage:records_entry`. Заполни payload по подсказкам в игре.

Готовый редактируемый инструмент: `market buy exp_double_free`.

`exploit -f ~/scripts/exp_double_free.adr -s storm_relay_outage:records_entry 198.22.91.1`

Прочитай `/srv/records/storm-status.txt` на последнем узле — там сохранённая запись.

## Установка и память

Семейство: события. Организация: корпорация. Папка плагина не трогает чужие сохранения; созданные устройства и задания сохраняются вместе с миром.
