# Постаматы

Ячейка 42 открылась дважды по одному и тому же коду получения.

## Начало

1. Положи эту папку рядом с другими плагинами и нажми «Перечитать».
2. Открой окно подсказки командой `parcel_locker_hubs_open` или нажми «Старт».
3. В терминале запусти `parcel_locker_hubs_start`.
4. Прочитай письмо «Постаматы: первая зацепка» в игровой почте.
5. Открой `http://198.22.11.1/` в игровом браузере и запусти `probe 198.22.11.1`.
6. Разобраться с контроллером и восстановить его рабочую запись.

## Подсказки

Механика взлома: cache_poisoning. Подсказки и параметры конкретного устройства даёт research.

- Если `probe` показывает активный файрвол, обойди его командой `firewall <адрес>`. При промахе попробуй ещё раз и следи за подозрением.
- На первом узле ищи собственную службу плагина — `parcel_dispatch`.
- Для доступа нужно слабое место «entry», а не просто утечка данных.
- Внутри устройства посмотри `/etc/maintenance-note.txt` — там адрес записи.
- Команда `parcel_locker_hubs_status` показывает прогресс без сброса.
- Награда: 100 ₵, выплачивается один раз. Повторный запуск Start не дублирует содержимое и не сбрасывает прохождение.

## Если хочешь готовое решение

`research -h 3 198.22.11.1 parcel_locker_hubs:records_entry`

Свой исходник: `exploit new ~/scripts/my_exploit.adr 198.22.11.1 parcel_locker_hubs:records_entry`. Заполни payload по подсказкам в игре.

Готовый редактируемый инструмент: `market buy exp_cache_poisoning`.

`exploit -f ~/scripts/exp_cache_poisoning.adr -s parcel_locker_hubs:records_entry 198.22.11.1`

Прочитай `/srv/records/deliveries.csv` на последнем узле — там сохранённая запись.

Семейство: устройства. Организация: корпорация. Папка плагина не трогает чужие сохранения; созданные устройства и задания сохраняются вместе с миром.
