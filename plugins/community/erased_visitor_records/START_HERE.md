# Стёртые записи о посетителях

Ресепшн и контроллер доступа не сошлись в показаниях о посетителе после работы.

## Начало

1. Положи эту папку рядом с другими плагинами и нажми «Перечитать».
2. Открой окно подсказки командой `erased_visitor_records_open` или нажми «Старт».
3. В терминале запусти `erased_visitor_records_start`.
4. Прочитай письмо «Стёртые записи о посетителях: первая зацепка» в игровой почте.
5. Открой `http://198.22.46.1/` в игровом браузере и запусти `probe 198.22.46.1`.
6. Отследить обоих свидетелей и восстановить цепочку хранения.

## Подсказки

- Если `probe` показывает активный файрвол, обойди его командой `firewall <адрес>`. При промахе попробуй ещё раз и следи за подозрением.
- На первом узле ищи собственную службу плагина — `visitor_archive`.
- Для доступа нужно слабое место «entry», а не просто утечка данных.
- Внутри устройства посмотри `/etc/maintenance-note.txt` — там адрес записи.
- Команда `erased_visitor_records_status` показывает прогресс без сброса.
- Награда: 215 ₵, выплачивается один раз. Повторный запуск Start не дублирует содержимое и не сбрасывает прохождение.

## Если хочешь готовое решение

`research -h 3 198.22.46.1 erased_visitor_records:gateway_entry`

Свой исходник: `exploit new ~/scripts/my_exploit.adr 198.22.46.1 erased_visitor_records:gateway_entry`. Заполни payload по подсказкам в игре.

Готовый редактируемый инструмент: `market buy exp_overflow`.

`exploit -f ~/scripts/exp_overflow.adr -s erased_visitor_records:gateway_entry 198.22.46.1`

Прочитай `/srv/records/visitor-records.csv` на последнем узле — там сохранённая запись.
