# Blackwire — механика игровых эксплоитов

Вся механика работает над вымышленными машинами World и сеансами Session. Сеть, адреса, файлы и payload относятся к модели игры. Adder не обращается к сокетам или процессам операционной системы пользователя.

## Путь игрока

1. `probe адрес` показывает работающие службы, версии, id уязвимостей и механику.
2. `research адрес id` раскрывает параметры конкретной цели и первую подсказку; `research -h 3 адрес id` — подробные подсказки.
3. `exploit new ~/scripts/mine.adr адрес id` создаёт заготовку и открывает игровой редактор.
4. Игрок пишет алгоритм, строящий словарь payload по исследованным данным.
5. `net.probe(адрес, id, payload)` проверяет payload без выдачи доступа; feedback объясняет ошибку.
6. `net.exploit(адрес, id, payload)` применяет подходящий удалённый payload. Для локального используется `net.privesc(payload, id)`.

Запуск исходника: `exploit -f ~/scripts/mine.adr -s id адрес` или `adder ~/scripts/mine.adr адрес id`. Локальный: `privesc ~/scripts/mine.adr id`, после получения оболочки на цели. Команды exploit/privesc без файла и net.exploit/net.privesc без payload доступ не выдают.

## Исследование и подсказки

net.vulns возвращает id, kind, service, port, version, name, access, local. Локальные слабые места нельзя исследовать с чужой машины. research выбирает точный id, полное имя либо службу, если она однозначна. При нескольких совпадениях требуется уточнение.

Профиль содержит fingerprint устройства и версии, layout с данными цели, fields с полями payload, hints с подсказками, market с id совместимого инструмента. В payload обязателен fingerprint. Профиль детерминирован по seed, устройству и уязвимой версии: сохранение/загрузка не меняют задачу, другая машина или версия требует нового исследования.

В игре доступны help research, help exploit, окно справки, заготовка с TODO в редакторе и кнопки «Подсказки» у плагинов. Правильный готовый payload не возвращается исследованием: его строит код игрока или купленный Adder-инструмент.

## Модели уязвимостей

| kind | Параметры исследования | Работа эксплоита |
| --- | --- | --- |
| overflow | frame_words, word_size, code_base, entry_offset, canary | Вычислить длину заполнения и адрес; сформировать buffer из букв A и суффикса `адрес и canary через вертикальные разделители` |
| traversal | mounts, target_file | Выйти через все вложенные каталоги с ../ и добавить путь к файлу без начальной / |
| auth_replay | account, challenge, salt, modulus | Вычислить взвешенную сумму символов строки challenge:salt по модулю modulus; отправить user и response |
| query | table, columns | Составить игровой запрос FIND с правильными таблицей, полями и обходом фильтра |
| format | stack_depth, argument_base, region_base, record_offset | Вычислить позицию аргумента и адрес записи; собрать позиционный format |
| protocol | nonce, capabilities | Собрать кадры HELLO, MODE и OPEN в нужном порядке |
| race | resource, window_ms | Составить расписание check → replace → use внутри игрового окна гонки |
| command_chain | command, parser, channel, nonce | Выбрать разделитель разборщика и составить цепочку с игровым bw-open |

Подробные правила формата возвращаются через research -h 3; для авторской подсказки используй -h 4. Payload ограничен 64 КиБ. Гонка проверяет виртуальные метки времени, реальное ожидание не требуется.

Все штатные уязвимости имеют модель. Пользовательские типы устройств и уязвимости получают её по службе/доступу либо явно через exploit.kind в SDK.

## Покупка и изменение исходников

Маркет продаёт 28 совместимых инструментов exp_<kind>; полный список механик приведён ниже. Исследование показывает подходящий id.

`market buy exp_overflow` списывает игровые деньги и устанавливает `~/scripts/exp_overflow.adr`. Исходник открыт в редакторе. При несоответствии механики инструмент сообщает нужный товар и прекращает попытку. Он сам исследует текущую версию и строит payload; защита и ограничения действуют так же, как для своего кода.

Купленные личные скрипты доступны из SSH-цепочки через ~/scripts/. Существующий файл на удалённой машине имеет приоритет и читается с правами текущего пользователя. Для личных инструментов используется только собственный каталог scripts компьютера игрока. Существующие файлы и изменённые покупки не перезаписываются. Удалённую купленную копию штатного товара можно восстановить повторной покупкой без оплаты.

Плагины могут продавать собственный исходник через plugin.catalog("market", ...). Его id можно связать с уязвимостью через exploit.market. Работающий пример: sdk/examples/device_lab.

## Последствия и ограничения

Исследование учитывает маршрут, доступность службы и файрвол. Пробы и отклонённые попытки пишутся в игровой журнал, на наблюдаемых целях увеличивают подозрение и могут выдать приманку. Сработавший payload применяет только доступ уязвимости: creds, shell, root, read либо info.

Shell добавляет hop текущего сеанса; найденные логины сохраняются в found_creds; read возвращает только результат конкретной уязвимости. Неправильный payload не меняет владельца, права и цепочку подключений. Успешный локальный и удалённый взлом создаёт on_hack для обработчиков SDK; проверка payload такого события не создаёт.

Рейд блокирует удалённые атаки и пробы, но оставляет локальное восстановление. Локальный payload требует текущего сеанса на машине. Остановленная/обновлённая служба, неверная версия, чужой fingerprint и неправильный id отклоняются.

SSH по известному паролю и crack по игровому словарю остаются отдельными механиками авторизации. clearlogs/wipe очищает следы с учётом прав, proxy показывает цепочку и источник, heat/trace — риск расследования.

## Устройство ядра

- hack/vuln.rs: обнаружение штатных и авторских уязвимостей.
- hack/payload.rs: стабильные id, выбор цели, профиль исследования, 28 валидаторов и подсказки; авторские типы используют проверку на Adder.
- script_host.rs: net.research, net.probe, net.exploit и net.privesc; до изменения прав проверяет payload.
- hack/exploit.rs и hack/privesc.rs: применение выбранного эффекта. Внутренние Rust-функции без payload нужны для моделирования и старых тестов ядра; игровой интерфейс их напрямую не предоставляет.
- shell/cmds_hack.rs: исследование, создание исходника и постановка Adder-скрипта в обычную очередь исполнения.
- market.rs, hack/exploits/*.adr: покупка и настоящий исходный код восьми инструментов.
- plugins/content.rs: правила exploit.kind/difficulty/hint/market; plugins/catalog.rs: продажа авторских инструментов.

Новых обязательных полей в сохранении не требуется. Определения авторских профилей хранятся в существующем словаре уязвимостей плагинов. Пакеты API 1 продолжают объявлять контент прежним способом; скрипты, использовавшие автоматический net.exploit без payload, нужно перевести на новый API.

## Проверка

player_exploits.rs исполняет настоящие купленные Adder-файлы через очередь Game и проверяет все штатные уязвимости, каждую модель, локальное повышение прав, отказ старого автоматического вызова, ошибочные payload, подсказки, сохранение/загрузку и защиту изменённых исходников.

Тесты SDK и community_plugins.rs используют те же Adder-эксплоиты для прохождения заданий. Сто плагинов проверяются последовательно, каждый в отдельном мире. Совместный нагрузочный прогон на пользовательском компьютере не запускается.

## Результаты взлома и условия

`research адрес id` и `net.research(адрес, id)` показывают `result` и `conditions`.
Каждое условие содержит `requirement`, `ok`, `observed`, `hint`. Правильный payload
не заменяет условия: `net.probe` и применение эксплоита проверяют их заново.
Покупной инструмент подчиняется тем же правилам. Условия соединяются через И.

В `plugin.vulnerability` можно задать дополнительные поля:

```python
plugin.vulnerability("report", {
    "device_type": device,
    "service": "http", "version_prefix": "1.", "access": "info",
    "exploit": {"kind": "traversal"},
    "result": {"type": "partial_file", "path": "/tmp/report.txt", "methods": ["read", "stat"]},
    "conditions": [
        {"type": "active_admin"},
        {"type": "connections_min", "count": 2},
        {"type": "plugin_state", "key": "door_open", "equals": true}
    ]
})
```

Если `result` отсутствует, действует прежнее поле `access`. Новый `result` имеет приоритет.
Поле `access` остаётся обязательным для совместимости; локальный эксплоит по-прежнему
повышает права до root, и его явный результат может быть только `shell`/`root`.

| result.type | Результат и разрешённые методы |
| --- | --- |
| shell | Реальный вход в терминал; privilege: guest, user или root. Необязательный user выбирает существующую учётную запись. |
| creds | Найденные логин и пароль; необязательный user выбирает учётную запись. |
| read | Однократная утечка файла; обязателен path. |
| info | Баннер службы. |
| computer | Объект: hostname, services, users, processes, read, write, list. |
| router | Объект: hostname, services, routes, connections. |
| file | Объект одного файла: read, write, stat; обязателен path. |
| partial_shell | Только явно указанные методы из whoami, hostname, read, list. Права файлов — выбранного пользователя. |
| partial_computer | Явное подмножество методов computer. |
| partial_router | Явное подмножество методов router. |
| partial_file | Явное подмножество методов file; обязателен path. |

У частичных объектов `methods` обязателен и не может быть пустым. У полных объектов
он необязателен и может сузить доступ. Путь должен быть абсолютным и нормализованным,
без `..`. Объекты computer/file представляют полученный эксплоитом доступ к данным
и действуют от root, если автор явно не указал существующего `user`.
Частичная оболочка по умолчанию использует обычного пользователя, при его отсутствии — guest.
Ни один объект не добавляет подключение в терминале или узел в список захваченных машин.
Объект router даёт просмотр маршрутизации, но не неявное управление всей сетью.

`net.exploit` для объекта возвращает `{ok:true, access, handle, methods, host, expires_in:300}`.
Дальнейшие действия выполняются **в том же сеансе терминала**:

```python
r = net.exploit(address, selector, payload)
if r["ok"] and "handle" in r:
    print(net.access(r["handle"], "read"))  # file/partial_file: только выданный файл
    # net.access(r["handle"], "write", "новый текст")
    # computer: net.access(handle, "read", "/tmp/report.txt")
    # computer: net.access(handle, "write", "/tmp/report.txt", "новый текст")
    # partial_shell: net.access(handle, "list", "/home/operator")
```

Другие методы не принимают аргументов. `hostname` и `whoami` возвращают строку;
`services`, `users`, `processes`, `routes`, `list` — списки; `connections` — число;
`stat` — сведения о файле; `write` — null. Вызов `exec` не поддерживается:
полноценный терминал выдаёт только результат shell. Объект истекает через 300 игровых
секунд, закрытие окна терминала его отзывает. Сохранение/загрузка не сохраняет
объекты доступа: после загрузки повтори взлом. Остановка/обновление службы,
недоступность узла, блокировка канала или изменение результата уязвимости
прерывают использование объекта. Условия проверяются при получении доступа;
уже выданный объект не отзывается только из-за выхода нужного пользователя.
Действия оставляют следы и повышают подозрение на наблюдаемых узлах.

| conditions.type | Параметры и смысл |
| --- | --- |
| active_user | Необязательный user: указанный пользователь активен, иначе любой обычный пользователь. |
| active_admin | Активен root или пользователь с правами администратора. init и демоны не считаются входом. |
| users_min / users_max | count: граница числа зарегистрированных учётных записей, включая root. |
| connections_min / connections_max | count: граница числа входящих соединений. |
| forwarded_ports_min | count: минимум проброшенных портов; открытый сервис сам по себе не является пробросом. |
| service_running | service: запущена указанная служба. |
| os_prefix | prefix: ОС начинается с этой строки. |
| file_exists | path: на узле существует файл или каталог. |
| time_window | start, end: часы 0..23 по игровым часам; начало включено, конец исключён. 23→7 пересекает полночь; одинаковые границы дают пустое окно. |
| same_lan | Текущий узел и цель находятся в одной локальной сети либо один является шлюзом другого. |
| plugin_state | key, equals: значение plugin.get владельца уязвимости равно equals. |

Можно задать не более 16 условий; count — целое 0..4096. Отсутствие `conditions`
не добавляет ограничений пользовательской уязвимости. Неизвестные типы и поля
отвергаются при регистрации. Обычный игрок не может передать «выполненные условия»
в payload: движок проверяет состояние мира самостоятельно.

Для сценариев с NPC и собственным сетевым оборудованием плагин с разрешением
`content` задаёт моделируемую активность:

```python
plugin.host_activity(mid, {
    "users": ["root", "operator"],
    "connections": 2,
    "forwarded_ports": [7002]
})
state = plugin.host_activity(mid)
plugin.set("door_open", true)
```

Это полная замена активности сценария на данном узле. Имена должны существовать;
connections — 0..4096, списки до 128 элементов, порты 1..65535. Значения сохраняются.
Настоящие сеансы игрока учитываются дополнительно; закрытие сеанса уменьшает
число соединений. Входы NPC живого мира тоже учитываются и истекают через
10 игровых минут. Системные процессы не делают администратора постоянно активным.

Рабочий пример: `sdk/examples/access_lab` (команды `access_create`, `access_ready`,
`access_reset`). Он демонстрирует 10 вариантов доступа, подсказки, покупку
`exp_protocol` и изменение условий. Пример `custom_vuln_type` показывает отдельную
возможность: полностью авторский тип проверки payload на Adder.

## Расширенные модели payload

Движок поддерживает 28 встроенных моделей: overflow, traversal, auth_replay, query, format, protocol, race, command_chain, integer_overflow, signedness, length_confusion, use_after_free, double_free, type_confusion, object_reference, mass_assignment, token_confusion, request_smuggling, cache_poisoning, header_injection, unsafe_deserialization, prototype_pollution, template_injection, xml_entity, regex_backtracking, fragment_overlap, weak_rng, permission_mask. Для каждой есть `exp_<kind>.adr` и покупной инструмент. Это ограниченные игровые модели: обработчики не выполняют реальные команды ОС или произвольные шаблоны.

### Полностью авторский тип на Adder

`kind = plugin.exploit_type("my_lock", {"name":"My Lock", "profile":"describe", "validate":"check"})` регистрирует тип `<plugin.id>:my_lock`. Далее передай его в `plugin.vulnerability(..., {"access":"shell", "service":"my_service", "exploit":{"kind":kind,"params":{"code":42}}})`.

`describe(event)` возвращает `{layout:словарь, fields:список_имён, hints:список_подсказок}`. `check(event)` возвращает bool либо `{ok:bool, feedback:строка}`. Событие содержит seed, device, vulnerability, params, profile; проверка также получает payload. Разрешены чистые вычисления и чтение `plugin.get`, `plugin.asset`; сетевые вызовы, изменение мира и ввод запрещены. Лимит — 20000 шагов и 150 мс. Не более 64 типов на плагин. При выключенном или отсутствующем плагине тип недоступен; исходный код не сохраняется в мире. Поле market определения типа может указать товар с готовым исходником. Рабочие profile/validate, продажа и удалённый/локальный вызов — в `examples/custom_vuln_type`.
