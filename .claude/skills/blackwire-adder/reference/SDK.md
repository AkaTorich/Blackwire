# Blackwire SDK — плагины на Adder

Версия API: **1**. Язык кода плагина — игровой **Adder**, расширение `.adr`.

## Установка и запуск

Открой «Плагины» на рабочем столе игры. «Открыть папку» показывает каталог пакетов текущего профиля: по умолчанию `%APPDATA%\top.blackwire.game\plugins`. Положи туда отдельную папку плагина и нажми «Перечитать». Папка содержит `plugin.json`, исходник и, при необходимости, библиотеки и ресурсы.

Кнопки «Добавить пример устройств» и «Добавить пример района» устанавливают встроенные примеры. Они не заменяют уже существующие папки. После установки в карточке появляются команды и собственные окна плагина. Команды можно нажимать кнопками или вводить в игровом терминале.

Выключение прекращает вызовы обработчиков. Уже созданные машины, файлы, задания и купленные товары остаются в мире; данные плагина сохраняются. Удаление папки пакета также не удаляет созданный контент из сохранения. Для возврата мира к состоянию до установки используй заранее сделанный слот сохранения.

## Первый плагин

Папка `my_counter`:

```json
{
  "id": "my_counter",
  "name": "Мой счётчик",
  "version": "1.0.0",
  "api": 1,
  "entry": "main.adr",
  "events": {"on_tick": "tick"},
  "commands": {"counter_show": "show"}
}
```

Файл `main.adr`:

```python
def tick(event):
    plugin.set("ticks", plugin.get("ticks", 0) + 1)

def show(event):
    print("Тактов мира:", plugin.get("ticks", 0))
```

Нажми «Перечитать», затем `counter_show`. Значение сохраняется вместе с игрой.

## Устройство пакета

Обязательные поля манифеста: `id`, `name`, `version`, `api`, `entry`. Неизвестные поля считаются ошибкой. `id` и имена функций/команд — ASCII-буквы, цифры и подчёркивание; первый символ не цифра, длина до 64. Имена встроенных команд переопределять нельзя.

Дополнительные поля:

| Поле | Значение |
| --- | --- |
| permissions | список разрешений |
| events | словарь «событие → имя функции» |
| commands | словарь «имя команды → имя функции» |
| libraries | список относительных путей к исходникам Adder; добавляются перед entry в указанном порядке |
| assets | список относительных путей к текстовым ресурсам UTF-8; читать через plugin.asset |
| requires | список id необходимых плагинов; задаёт порядок загрузки |

Каждый обработчик принимает один словарь `event`. Возвращаемое значение обычной функции игнорируется. `print` попадает в ответ команды, а ошибки — в карточку плагина. Вывод фонового обработчика сам по себе не создаёт уведомление: для него используй `sys.notify`.

Для фоновых событий плагин имеет собственный игровой сеанс: текущие машина, пользователь и папка сохраняются между событиями в рамках запущенной игры. Команда плагина работает в сеансе вызвавшего её терминала. При выключении или перечитывании пакета его служебный сеанс закрывается вместе с принадлежащими ему скриптами.

Исходник выполняется заново на каждом событии. На верхнем уровне держи определения функций и константы; регистрацию содержимого выполняй в `on_load`. Для долговременных данных используй `plugin.get/set`, а не глобальные переменные Adder. Библиотеки также исполняются заново. Номера строк ошибки относятся к объединённому тексту libraries + entry + вызов обработчика.

Плагины загружаются в порядке зависимостей, независимые — по id. Не найденная зависимость и цикл отмечаются ошибкой. Используй разные id пакетов и разные имена команд. Версия `api` должна совпадать с версией движка; поле `version` описывает версию самого пакета.

## Разрешения

| Разрешение | Возможности |
| --- | --- |
| без разрешений | своё хранилище plugin.get/set, данные события, объявленные assets |
| content | создание/изменение игрового мира, типов устройств, уязвимостей, каталогов, заданий, окон, таймеров |
| sys | игровые sys-функции: сведения, уведомления, открытие приложений; sys.kill в обработчике запрещён |
| fs | обычные операции с виртуальными файлами в правах текущего игрового сеанса |
| net | обычные игровые сетевые действия в правах текущего игрового сеанса |
| shell | команды игровой оболочки через shell.exec; это также даёт доступ к механикам, реализованным командами |
| time | игровые вызовы хоста time.now |
| network | отправка и приём сообщений через уже подключённую сетевую партию игры |

`content` — авторские полномочия над игровым миром. Это существенно шире прав обычного персонажа. `net` означает вымышленную сеть игры, `network` — канал установленной многопользовательской партии. Через SDK нет API чтения произвольных файлов Windows или запуска команд Windows.

## События

| Событие | Когда и что передаётся |
| --- | --- |
| on_load | загрузка, перечитывание или включение пакета; пустой словарь |
| on_tick | вызов Game.tick; dt_ms — прошедшие миллисекунды |
| on_command | завершение встроенной команды игрока; line, session |
| on_hack | успешный результат игрового exploit; target, target_host, vuln (объект; имя в vuln["name"]), outcome, source_ip, monitored, heat_added |
| on_mail | новое входящее письмо после шага мира: direction=inbox, mail; отправка через Game.mail_send: direction=sent, to, subject, body |
| on_mission_done | продвижение сюжетной цепочки; before, active |
| on_gig_done | изменение числа выполненных подработок; before, done |
| on_purchase | покупка; catalog=shop/market, id |
| on_achievement | открыто достижение; id |
| on_investigation | смена стадии слежки; before, stage, progress |
| on_scenario_done | завершён активный сценарий; scenario |
| on_world | изменилось число машин или организаций; machines, orgs |
| on_file | изменение через редактор/файловое окно или файловый API Adder; operation и сведения об операции |
| on_ui | кнопка собственного окна; window, action, values |
| on_network | пакет установленной партии; plugin, channel, data, from |
| on_save | перед сохранением основного профиля |
| on_unload | выключение пакета или выход через игровую команду quit |
| custom.имя | адресное событие таймера этого плагина; timer, data |

События изменения состояния формируются после действия оболочки, API Adder и шага мира. Изменения, которые делает обработчик, не вызывают синхронный рекурсивный запуск другого обработчика. Проверки собственных произвольных условий удобно делать в `on_tick` или по таймеру. Прямое закрытие процесса Windows не гарантирует on_unload; важные данные сохраняй по ходу работы.

## Основные функции

Все `plugin.*` ниже вызываются только из плагина. JSON-значения превращаются в обычные словари, списки, строки, числа и null Adder.

| Вызов | Результат / действие |
| --- | --- |
| plugin.id() | id текущего плагина |
| plugin.event() | словарь текущего события |
| plugin.get(key, default=null) | значение своего сохранённого ключа |
| plugin.set(key, value) | сохранить значение; ключ до 128 символов, данные одного плагина до 64 КБ |
| plugin.asset(path) | строка объявленного текстового ресурса |
| plugin.world() / plugin.world("overview") | полное состояние мира / облегчённые данные для отчётов |
| plugin.apply(patch) | атомарно заменить указанные разделы игрового состояния после проверки |
| plugin.random(lo, hi) | целое из [lo, hi), генератор мира; границы в пределах ±10^9 |

Пример изменения экономики:

```python
world = plugin.world()
world["finance"]["rate_per_day"] = 1.0
plugin.apply({"finance": world["finance"]})
```

`apply` принимает разделы `machines`, `orgs`, `player`, `missions`, `finance`, `ending`, `life`, `gigs`, `market`, `base`, `achievements`, `scenarios`, `investigation`, `fw_down`, `keyloggers`, `botnet`, `botnet_mined`, `defense`, `down_until`. Несколько разделов можно изменить одним вызовом, например одновременно машины и организации. Структура — та же, что в `plugin.world()`; примеры реальных объектов лежат в `sdk/schema`.

Движок проверяет типы, идентификаторы, ссылки, порты, адреса и маршруты. Нельзя удалить существующую машину/организацию, подменить личность игрока, удалить пользователя активного сеанса или создать цикл маршрутизаторов. Чтобы убрать устройство из работы, установи `up=false`. Часы, внутренний генератор, очереди и чужие данные плагинов через apply не заменяются.

## Типы устройств

| Вызов | Назначение |
| --- | --- |
| plugin.template(base_kind) | готовый шаблон настоящего генератора игры |
| plugin.device_type(key, template) | зарегистрировать собственный тип; возвращает `plugin_id:key` |
| plugin.spawn(type_id, properties) | создать экземпляр; возвращает новый числовой id |
| plugin.machine(id) | копия одной машины |
| plugin.update_machine(id, properties) | частичное изменение машины с проверкой связей |
| plugin.user(id, name, password, admin=false) | добавить игровую учётную запись и домашнюю папку |
| plugin.write(id, path, text) | авторская запись в виртуальный файл; создаёт родительские папки |

Базовые виды: `player`, `home_pc`, `router`, `gateway`, `server`, `workstation`, `database`, `file_server`, `mail`, `web`, `camera`, `badge`, `atm`, `medical_device`, `dns`, `isp`, `honeypot`.

Собственный тип — отдельный `device_type` с любым содержимым на основе базового поведения. Например, датчик, промышленный контроллер или спутниковый модем получают своё имя типа, ОС, оборудование, службы, файлы, пользователей и уязвимости. Особое поведение реализуется Adder-обработчиками. Новые нативные графические примитивы или инструкции интерпретатора требуют изменения самого движка.

```python
def load(event):
    template = plugin.template("camera")
    template["os"] = "SensorOS 1.0"
    template["org"] = null
    template["router"] = null
    template["services"] = [{"port": 9000, "name": "sensor", "version": "1.0", "running": true, "banner": "Sensor control", "pages": []}]
    plugin.device_type("sensor", template)

def create(event):
    mid = plugin.spawn("my_plugin:sensor", {"hostname": "sensor-1", "ip": "198.18.10.1", "lan_ip": null, "domain": null, "up": true})
    plugin.user(mid, "operator", "sensor123", false)
    plugin.write(mid, "/etc/sensor/config.txt", "mode=normal\n")
```

`id` выдаётся автоматически, hostname и IP должны быть уникальны. Для внутреннего устройства укажи `lan_ip`, `router`, организацию и маршрут. Добавь id в `player.known_machines`, если оно должно сразу появиться на карте. Строка device_type отображается в карточке карты и neofetch; прочие правила поведения продолжают учитывать базовый kind.

## Собственные уязвимости

`plugin.vulnerability(key, spec)` регистрирует правило и возвращает namespaced id. Правило применяется к существующим устройствам и при появлении/изменении новых. Оно участвует в обычных `probe`, `net.vulns`, `exploit` и локальном повышении прав.

| Поле spec | Назначение |
| --- | --- |
| device_type | необязательно; только этот тип устройства |
| machine | необязательно; только этот числовой id устройства |
| service | имя удалённой службы |
| version_prefix | префикс версии службы; для local — префикс ОС; пусто означает все версии |
| access | creds, shell, root, info или read:/абсолютный/путь |
| local | true для локальной уязвимости ядра, false по умолчанию |
| handler | необязательно; имя Adder-функции дополнительных последствий успешного удалённого exploit |

Если указаны и device_type, и machine, должны совпасть оба условия. Для любого устройства можно зарегистрировать отдельные уязвимости. Для удалённой уязвимости служба должна работать и совпадать по имени/версии. Обновлённая версия службы перестаёт подходить старому правилу.

```python
plugin.vulnerability("sensor_default_login", {
    "device_type": "my_plugin:sensor",
    "service": "sensor",
    "version_prefix": "1.",
    "access": "shell"
})
plugin.vulnerability("sensor_42_overload", {
    "machine": 42,
    "service": "sensor",
    "version_prefix": "1.0",
    "access": "info",
    "handler": "overload"
})

def overload(event):
    plugin.update_machine(event["target"], {"up": false})
    plugin.news("Один из датчиков перестал отвечать.")
```

Когда у одной службы несколько уязвимостей, можно выбрать конкретную: `exploit -s my_plugin:sensor_42_overload адрес`. Без выбора движок использует первую подходящую. Уязвимости проходят через обычные игровые файрволы, маршруты и следы. Локальные правила используются `privesc` и требуют access=root; handler относится к удалённому exploit.

## Службы, сайты, организации и почта

| Вызов | Формат |
| --- | --- |
| plugin.service(machine, spec) | port, name, version, running, banner, pages; заменяет службу на этом порту |
| plugin.page(machine, port, spec) | path, title, html; добавляет/заменяет страницу существующей службы |
| plugin.org(spec) | name, kind, domain, gateway, subnet, members, description; id выдаётся автоматически |
| plugin.mail(machine, spec) | from, subject, body, необязательный to; входящее письмо на указанной машине |
| plugin.log(machine, kind, text) | login, login_failed, logout, exec, file_change, service, net, warn |
| plugin.news(text) | новость в обычной городской ленте |

Создавай сначала машины без организации, затем организацию с их id в members. `plugin.org` обновляет поле org у перечисленных машин. Маршрутизация задаётся router и lan_ip. Вид организации берётся из штатных corporation, bank, hospital, security_center, cyber_police, isp, university, hosting, government, media, shop, home, honeypot, underground.

Сайт открывается настоящим игровым браузером. HTML страницы проходит через существующий рендерер браузера игры; это контент виртуальной сети. Для собственных интерактивных инструментов используй окна плагина.

## Задания и сценарии

`plugin.quest(key, {title, objective, reward})` создаёт независимое задание плагина. Возвращает `plugin_id:key`. Повторная регистрация не сбрасывает выполнение. `plugin.quest_complete(id)` начисляет награду один раз и возвращает true при первом выполнении, false при повторе. Условия может проверять любой Adder-код: число устройств, конкретный файл, состояние службы, покупка, таймер, письмо, комбинация действий. Задания видны в missions и на gate.hw/board.

`plugin.gig(spec)` добавляет настоящую подработку: title, objective, reward, goal. Поддерживаются штатные цели `{"Own":{"target":42}}` и `{"Deliver":{"target":42,"path":"/srv/data.txt","needle":"метка"}}`. Id выдаётся автоматически.

`plugin.scenario(spec)` запускает сценарий редактора: name, brief, goal, reward. Штатные условия: `{"OwnHost":{"host":"server-name"}}`, `{"Deliver":{"needle":"метка"}}`, `{"Money":{"amount":1000}}`. Одновременно активен один такой сценарий; собственные quest могут работать параллельно.

Сюжетную цепочку можно расширять через раздел missions в apply. Там используются реальные MissionRun и Goal: ReadDeliver, Own, Plant, CoverTracks. Меняй согласованно active и status. Для независимых дополнений предпочтительнее quest, чтобы не менять условие завершения основной истории.

## Магазин, маркет и достижения

`plugin.catalog(kind, key, item)` добавляет запись. kind: shop, market, achievements. item содержит name, desc, необязательную price; для market также file и code. Id возвращается как `plugin_id:key`.

Записи shop видны через shop и gate.hw/shop, приобретаются командой buy. Факт покупки находится в player.upgrades. Реализуй действие улучшения в on_purchase или on_tick и сохраняй признак уже применённого эффекта.

Записи market видны через market и gate.hw/market. Покупка market buy id кладёт объявленный код Adder в ~/scripts/file и списывает цену. Имя file — только имя .adr без каталогов. Подбирай уникальное имя файла для своего пакета.

Записи achievements видны в achievements/ach. `plugin.unlock("plugin_id:key")` открывает достижение. Условие проверяет сам плагин. Покупки и награды используют штатный баланс игры.

## Таймеры и живой мир

`plugin.timer(key, delay_seconds, event, payload=null, repeat_seconds=0)` создаёт адресный таймер этого плагина. delay: 1..31536000; event начинается с custom. и объявляется в events манифеста. repeat=0 — однократный. Повторная регистрация того же key заменяет таймер. `plugin.cancel_timer(key)` отменяет его.

Таймеры хранятся в сохранении и проверяются при шагах мира. При большом скачке времени пропущенные повторы не воспроизводятся все сразу: срабатывание одно, следующий срок считается от текущего времени. При выключенном плагине таймер не выполняется. После включения просроченный таймер сработает на следующем шаге.

Новости, письма, изменение служб, файлов, процессов и состояния защиты позволяют создавать собственную симуляцию. Для воспроизводимых решений бери plugin.random, связанный с генератором мира.

## Собственные окна

`plugin.window(key, spec)` регистрирует или обновляет окно. Возвращает `plugin_id:key`. `plugin.open(id)` открывает его как отдельное настоящее окно игры. Также окно доступно кнопкой в карточке плагина.

```python
plugin.window("control", {
    "title": "Управление датчиками",
    "text": "Создание и обслуживание сети",
    "fields": [{"id": "count", "label": "Количество", "type": "number", "value": 3}],
    "rows": [["Состояние", "Готово"]],
    "buttons": [{"id": "generate", "label": "Создать"}]
})
```

fields поддерживает text, number, checkbox. rows — список строк таблицы. Нажатие передаётся в on_ui: `event["window"]`, `event["action"]`, `event["values"]`. После обработчика окно перечитывает своё описание; обновление делается новым plugin.window с тем же key. Используется стандартный вид игры, все надписи вставляются как текст. Произвольный JS с доступом к Tauri плагину не выдаётся; логика остаётся на Adder.

## Сетевая игра

`plugin.network()` возвращает состояние подключения: role и snap (mode, phase, seed, targets, peers и другие поля штатной партии). До подключения сведения могут быть null. `plugin.net_send(channel, data)` отправляет до 16 КБ данных через существующую партию. Разрешение network обязательно. Приём идёт в on_network только установленному, включённому плагину с тем же id и разрешением network. from задаётся транспортом игры.

Канал позволяет писать собственные кооперативные события и обмен данными. Исходники пакетов, весь мир и пользовательские каталоги автоматически не передаются. У участников должны быть совместимые версии плагина; правила общей игровой логики реализуются самим плагином. Доход и создание контента каждого игрока остаются в его локальном мире, как в штатной сетевой игре.

## Проверка без окон

`plugin-check.exe` использует настоящее ядро Blackwire и создаёт отдельный тестовый мир с seed=42 и игроком sdk_test. Сохранения игрока не читает и не меняет.

```text
plugin-check.exe sdk\examples --command district_create --command lab_create --ticks 65
plugin-check.exe папка-плагинов --command "команда аргументы" --ticks 10
```

Можно передать папку одного пакета с plugin.json или родительский каталог, каждая подпапка которого рассматривается как пакет. Опции идут после пути; --command можно повторять, --ticks допускает до 3600 шагов. --dump-world путь.json записывает тестовый мир; --dump-shell путь.md записывает справку реальных команд движка. Ошибка манифеста, обработчика или команды даёт ненулевой код завершения.

Для разработки из исходников:

```text
cargo run -p blackwire-core --bin plugin-check -- sdk/examples --command district_create --ticks 65
cargo test -p blackwire-core plugins::tests
cargo test --workspace --jobs 2
```

Adder-check остаётся проверкой обычных скриптов языка. Для плагинов обязательно используй plugin-check: он вызывает реальные обработчики, проверяет API и видит настоящий мир. Одна проверка синтаксиса не доказывает работоспособность плагина.

## Ошибки и границы API

Ошибка останавливает этот плагин; движок продолжает работать. Изменения мира, сеансов, очереди UI, запланированных скриптов и сетевого исходящего буфера текущего обработчика откатываются. Ранее успешно созданный контент остаётся. Включение заново или «Перечитать» повторяет on_load.

На обработчик выделено 50000 шагов интерпретатора; остановка не ловится try/except. Дополнительно проверяется время около 500 мс между периодическими проверками. Это кооперативные ограничения, а не отдельный процесс с жёсткой квотой памяти; крупные операции разбивай на таймеры и используй доверенные пакеты. input не блокирует игру — он выдаёт ошибку. sleep прерывает обработчик при следующей проверке; для задержек нужен таймер.

Размер entry и одного ресурса — до 256 КБ; объединённого исходника до 1 МБ, текстовых assets до 2 МБ; до 128 пакетов и 4096 устройств. Вывод команды ограничен 100 строками по 4096 символов.

В API 1 зарегистрированные команды плагинов запускаются отдельной командой, без конвейеров и перенаправления. Внутри плагина shell.exec работает с обычными возможностями встроенной оболочки. Вложенный синхронный вызов команды другого плагина не поддерживается. Для обмена общим контентом используй мир, зависимости и события.

## Сквозные примеры

`device_lab`: новый тип камеры, служба lab_control, уязвимость только типа, локальное повышение прав и уязвимость конкретного экземпляра; команды lab_create и lab_info.

`district`: генерирует шлюз и внутренний архив, организацию, подсеть, сайт, файлы, учётные записи, письмо и задание; добавляет улучшение в магазин, скрипт в маркет и достижение; создаёт своё окно и повторяющиеся новости; обработчик уязвимости записывает последствия в виртуальный мир. Команды district_create, district_open, district_status.

Исходники обоих пакетов входят в SDK и руководство. Они показывают реальные форматы текущего API.

## Облегчённые отчёты

Для панелей состояния используй `plugin.world("overview")`. Он возвращает разделы player, orgs, finance, investigation и список machines с полями id, hostname, ip, lan_ip, router, kind, os, up, ram_mb, disk_mb, services, custom_vulns, четырьмя последними записями logs и заголовками mail (from, subject, read). Раздел plugins содержит quests, catalogs и device_types только с kind и os.

Этот режим не копирует виртуальные файловые системы, базы пользователей и полные шаблоны устройств. Для одной полной машины используй `plugin.machine(id)`. Вызов `plugin.world()` без аргументов по-прежнему возвращает полное состояние для редактирования. Неизвестный режим вызывает ошибку.

Поле `event["vuln"]` события on_hack — объект описания найденной уязвимости. Для проверки её имени сравнивай `event["vuln"]["name"]` с полным именем вида `plugin_id:rule_id`.
