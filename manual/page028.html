Устройство пакета

Обязательные поля манифеста: id, name, version, api, entry. Неизвестные поля считаются ошибкой. id и имена функций/команд — ASCII-буквы, цифры и подчёркивание; первый символ не цифра, длина до 64. Имена встроенных команд переопределять нельзя.

Дополнительные поля:

ПолеЗначение
permissionsсписок разрешений
eventsсловарь «событие → имя функции»
commandsсловарь «имя команды → имя функции»
librariesсписок относительных путей к исходникам Adder; добавляются перед entry в указанном порядке
assetsсписок относительных путей к текстовым ресурсам UTF-8; читать через plugin.asset
requiresсписок id необходимых плагинов; задаёт порядок загрузки

Каждый обработчик принимает один словарь event. Возвращаемое значение обычной функции игнорируется. print попадает в ответ команды, а ошибки — в карточку плагина. Вывод фонового обработчика сам по себе не создаёт уведомление: для него используй sys.notify.

Для фоновых событий плагин имеет собственный игровой сеанс: текущие машина, пользователь и папка сохраняются между событиями в рамках запущенной игры. Команда плагина работает в сеансе вызвавшего её терминала. При выключении или перечитывании пакета его служебный сеанс закрывается вместе с принадлежащими ему скриптами.

Исходник выполняется заново на каждом событии. На верхнем уровне держи определения функций и константы; регистрацию содержимого выполняй в on_load. Для долговременных данных используй plugin.get/set, а не глобальные переменные Adder. Библиотеки также исполняются заново. Номера строк ошибки относятся к объединённому тексту libraries + entry + вызов обработчика.

Плагины загружаются в порядке зависимостей, независимые — по id. Не найденная зависимость и цикл отмечаются ошибкой. Используй разные id пакетов и разные имена команд. Версия api должна совпадать с версией движка; поле version описывает версию самого пакета.
