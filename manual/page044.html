Результаты взлома и условия

research адрес id и net.research(адрес, id) показывают result и conditions. Каждое условие содержит requirement, ok, observed, hint. Правильный payload не заменяет условия: net.probe и применение эксплоита проверяют их заново. Покупной инструмент подчиняется тем же правилам. Условия соединяются через И.

В plugin.vulnerability можно задать дополнительные поля:

plugin.vulnerability("report", {
    "device_type": device,
    "service": "http", "version_prefix": "1.", "access": "info",
    "exploit": {"kind": "traversal"},
    "result": {"type": "partial_file", "path": "/tmp/report.txt", "methods": ["read", "stat"]},
    "conditions": [
        {"type": "active_admin"},
        {"type": "connections_min", "count": 2},
        {"type": "plugin_state", "key": "door_open", "equals": true}
    ]
})

Если result отсутствует, действует прежнее поле access. Новый result имеет приоритет. Поле access остаётся обязательным для совместимости; локальный эксплоит по-прежнему повышает права до root, и его явный результат может быть только shell/root.

result.typeРезультат и разрешённые методы
shellРеальный вход в терминал; privilege: guest, user или root. Необязательный user выбирает существующую учётную запись.
credsНайденные логин и пароль; необязательный user выбирает учётную запись.
readОднократная утечка файла; обязателен path.
infoБаннер службы.
computerОбъект: hostname, services, users, processes, read, write, list.
routerОбъект: hostname, services, routes, connections.
fileОбъект одного файла: read, write, stat; обязателен path.
partial_shellТолько явно указанные методы из whoami, hostname, read, list. Права файлов — выбранного пользователя.
partial_computerЯвное подмножество методов computer.
partial_routerЯвное подмножество методов router.
partial_fileЯвное подмножество методов file; обязателен path.

У частичных объектов methods обязателен и не может быть пустым. У полных объектов он необязателен и может сузить доступ. Путь должен быть абсолютным и нормализованным, без ... Объекты computer/file представляют полученный эксплоитом доступ к данным и действуют от root, если автор явно не указал существующего user. Частичная оболочка по умолчанию использует обычного пользователя, при его отсутствии — guest. Ни один объект не добавляет подключение в терминале или узел в список захваченных машин. Объект router даёт просмотр маршрутизации, но не неявное управление всей сетью.

net.exploit для объекта возвращает {ok:true, access, handle, methods, host, expires_in:300}. Дальнейшие действия выполняются в том же сеансе терминала:

r = net.exploit(address, selector, payload)
if r["ok"] and "handle" in r:
    print(net.access(r["handle"], "read"))  # file/partial_file: только выданный файл
    # net.access(r["handle"], "write", "новый текст")
    # computer: net.access(handle, "read", "/tmp/report.txt")
    # computer: net.access(handle, "write", "/tmp/report.txt", "новый текст")
    # partial_shell: net.access(handle, "list", "/home/operator")

Другие методы не принимают аргументов. hostname и whoami возвращают строку; services, users, processes, routes, list — списки; connections — число; stat — сведения о файле; write — null. Вызов exec не поддерживается: полноценный терминал выдаёт только результат shell. Объект истекает через 300 игровых секунд, закрытие окна терминала его отзывает. Сохранение/загрузка не сохраняет объекты доступа: после загрузки повтори взлом. Остановка/обновление службы, недоступность узла, блокировка канала или изменение результата уязвимости прерывают использование объекта. Условия проверяются при получении доступа; уже выданный объект не отзывается только из-за выхода нужного пользователя. Действия оставляют следы и повышают подозрение на наблюдаемых узлах.

conditions.typeПараметры и смысл
active_userНеобязательный user: указанный пользователь активен, иначе любой обычный пользователь.
active_adminАктивен root или пользователь с правами администратора. init и демоны не считаются входом.
users_min / users_maxcount: граница числа зарегистрированных учётных записей, включая root.
connections_min / connections_maxcount: граница числа входящих соединений.
forwarded_ports_mincount: минимум проброшенных портов; открытый сервис сам по себе не является пробросом.
service_runningservice: запущена указанная служба.
os_prefixprefix: ОС начинается с этой строки.
file_existspath: на узле существует файл или каталог.
time_windowstart, end: часы 0..23 по игровым часам; начало включено, конец исключён. 23→7 пересекает полночь; одинаковые границы дают пустое окно.
same_lanТекущий узел и цель находятся в одной локальной сети либо один является шлюзом другого.
plugin_statekey, equals: значение plugin.get владельца уязвимости равно equals.

Можно задать не более 16 условий; count — целое 0..4096. Отсутствие conditions не добавляет ограничений пользовательской уязвимости. Неизвестные типы и поля отвергаются при регистрации. Обычный игрок не может передать «выполненные условия» в payload: движок проверяет состояние мира самостоятельно.

Для сценариев с NPC и собственным сетевым оборудованием плагин с разрешением content задаёт моделируемую активность:

plugin.host_activity(mid, {
    "users": ["root", "operator"],
    "connections": 2,
    "forwarded_ports": [7002]
})
state = plugin.host_activity(mid)
plugin.set("door_open", true)

Это полная замена активности сценария на данном узле. Имена должны существовать; connections — 0..4096, списки до 128 элементов, порты 1..65535. Значения сохраняются. Настоящие сеансы игрока учитываются дополнительно; закрытие сеанса уменьшает число соединений. Входы NPC живого мира тоже учитываются и истекают через 10 игровых минут. Системные процессы не делают администратора постоянно активным.

Рабочий пример: sdk/examples/access_lab (команды access_create, access_ready, access_reset). Он демонстрирует 10 вариантов доступа, подсказки, покупку exp_protocol и изменение условий. Пример custom_vuln_type показывает отдельную возможность: полностью авторский тип проверки payload на Adder.
