Собственные уязвимости

plugin.vulnerability(key, spec) регистрирует правило и возвращает namespaced id. Правило применяется к существующим устройствам и при появлении/изменении новых. Оно участвует в обычных probe, net.vulns, exploit и локальном повышении прав.

Поле specНазначение
device_typeнеобязательно; только этот тип устройства
machineнеобязательно; только этот числовой id устройства
serviceимя удалённой службы
version_prefixпрефикс версии службы; для local — префикс ОС; пусто означает все версии
accesscreds, shell, root, info или read:/абсолютный/путь
localtrue для локальной уязвимости ядра, false по умолчанию
handlerнеобязательно; имя Adder-функции дополнительных последствий успешного удалённого exploit

Если указаны и device_type, и machine, должны совпасть оба условия. Для любого устройства можно зарегистрировать отдельные уязвимости. Для удалённой уязвимости служба должна работать и совпадать по имени/версии. Обновлённая версия службы перестаёт подходить старому правилу.

plugin.vulnerability("sensor_default_login", {
    "device_type": "my_plugin:sensor",
    "service": "sensor",
    "version_prefix": "1.",
    "access": "shell"
})
plugin.vulnerability("sensor_42_overload", {
    "machine": 42,
    "service": "sensor",
    "version_prefix": "1.0",
    "access": "info",
    "handler": "overload"
})

def overload(event):
    plugin.update_machine(event["target"], {"up": false})
    plugin.news("Один из датчиков перестал отвечать.")

Когда у одной службы несколько уязвимостей, можно выбрать конкретную: exploit -s my_plugin:sensor_42_overload адрес. Без выбора движок использует первую подходящую. Уязвимости проходят через обычные игровые файрволы, маршруты и следы. Локальные правила используются privesc и требуют access=root; handler относится к удалённому exploit.
